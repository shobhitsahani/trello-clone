Modular monolith · Postgres SOR (+RLS) · Redis (cache + rate-limit + pubsub + BullMQ) · signed-URL blobs · Postgres FTS

Tenant isolation — the hard invariant

  • • Shared-schema multi-tenancy + Postgres RLS as the backstop
  • • tenant_id in the PK of every tenant table, set from the request context
  • • A missing WHERE clause is a query error — not a data leak
  • • Search (tsvector+GIN) is tenant-scoped through the same mechanism

Scale-driven choices

  • • 30k DAU ⇒ ~120 peak read QPS, ~20 peak write QPS (BOTEC)
  • • One Postgres node ≫ write load ⇒ no sharding, no Kafka
  • • Redis = cache-aside + rate-limit + pub/sub + BullMQ transport
  • • Attachments (~7 TB/yr) live in blob store; metadata stays in Postgres

Degradation & breaking points

  • • Postgres down → fail-fast 503; replica reads with stale:true
  • • Redis down → cache-aside correct-but-slower; local limiters
  • • WS down → reconnect w/ backoff + cursor catch-up from notifications
  • • Design bends at ~300–500 write QPS, ~50M search docs, or an isolation-demanding tenant
